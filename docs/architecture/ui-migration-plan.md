# 桌面 UI 单实现整改计划

## 目标

当前只维护 `ui/` 下的一套产品界面。整改的目标是缩小单文件、统一叠层和交互、抽取可测业务规则，而不是在仓库中预先维护第二套页面。

## 固定边界

```text
ui/ 唯一页面与交互
        -> TypeScript/JavaScript 业务状态、规则、controller
        -> packages/tauri-api
        -> Rust command / domain / storage

唯一阅读页 <-> 有类型的协议边界 <-> 命令式 EPUB/PDF 引擎
```

- 业务规则和 Tauri 调用可从 UI 中抽离，但不创建另一个可视页面。
- 所有全屏信息页通过共享 `overlay-stack` 申明语义层级，不按页面 ID 特判 `z-index`。
- 单个功能的加载、错误、空态与取消都在同一页面内表达。
- 阅读引擎保持命令式 DOM/Canvas 渲染，不将高频帧状态上移到业务 UI。

## 整改优先级

1. 统一信息页、确认页和操作页的叠层及焦点恢复。
2. 继续把过滤、排序、同步、恢复和阅读统计规则抽成无视图模块。
3. 将大型 UI 文件按功能 controller 和样式边界拆分，但保持一个装配入口。
4. 使用固定 EPUB/PDF/大书库样本锁定性能与行为。
5. 任何可视改动后构建完整应用，安装到 `/Applications/鲲鹏阅读器.app` 后验收。

## 禁止项

- 不得复制一份页面用于候选、回退或 A/B 运行。
- 不得添加候选 UI iframe、双轨 loader、隐藏备用 DOM 或“打开旧版”入口。
- 不得为了目录或后缀统一而全量重写。
- 不得借 UI 整改静默改变 contracts、同步冲突或删除语义。

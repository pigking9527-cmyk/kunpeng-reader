# 桌面端单 UI 长期整改手册

> 状态：执行中。本文落实 ADR-0030，适用于多会话协作。

## 成功定义

1. 产品中每个业务只有一个用户可达的页面和一套样式。
2. 当前唯一可视实现位于 `ui/`；`apps/desktop-ui/` 只保留 TypeScript 状态、规则、controller 和 port。
3. 页面不通过 iframe、loader、隐藏 DOM 或“新版/旧版”按钮并存。
4. EPUB/PDF 引擎可保持独立渲染边界，但仍从唯一阅读页进入。

## 并行开发边界

- 功能会话可并行抽取无视图的纯规则、状态机、Tauri 适配层与测试。
- `ui/index.html`、`ui/reader.html`、`ui/styles.css` 和全局叠层管理是共享热点，同一时间只能有一个已登记会话修改。
- 不得为“先做候选页”新建任何可视实现。实验性视觉稿放在产品代码之外，不接入构建和测试。
- 涉及同步、删除、账户和恢复语义时，仍先更新 ADR、`contracts/` 和兼容 fixture。

## 单个页面整改流程

1. 在 `ACTIVE_WORK.md` 登记页面、相邻样式与测试的精确范围。
2. 用现有用户路径记录成功、空态、失败、取消、关闭和重启行为。
3. 先抽取可测的纯规则和原生边界，保持现行 UI 不变。
4. 直接在现行页面内改进结构与交互，不复制整页。
5. 运行相邻测试、全量桌面检查和完整 macOS 应用构建；然后安装并启动验收应用。

## 技术栈替换规则

如果未来确实要更换可视层技术，需新 ADR 批准。一个完整业务页是最小切换单元，同一变更必须完成新页验收，并同时删除旧页的入口、DOM、样式与测试。回滚单位是 Git 提交或发布版本，不是产品内的另一套 UI。

# 新仓库知识产权验收清单

新仓库只能从当前整改后的工作树制作无历史快照；不得 fork、mirror、导入旧
Git 历史或复制旧 Release。新仓库不能消灭旧分发已经产生的义务，因此旧库和
Release 证据必须在受控档案中保留到法律顾问批准销毁为止。

## 自动阻断项

- 不存在 `vendor/epub/`、`epub` 2.x、GPL/AGPL/LGPL 运行时依赖。
- 不存在旧的 MOE/Moedict 转换数据、OpenHowNet 数据导出或 `wordfreq` 派生表。
- ECDICT 和 CC-CEDICT 资产必须能用仓库生成器从固定哈希来源复现。
- 所有 Cargo/npm 包有许可元数据，锁文件、第三方通知和许可原文完整。
- 未经单独批准，不得包含 NVIDIA/CUDA/cuDNN 二进制或下载地址。
- 发行包必须包含第一方许可证、第三方通知、依赖许可证归档和数据来源说明。

## 必须由权利人签字确认

- 根许可证中的版权主体是真实、明确并有权授权的个人或公司。
- 所有第一方代码确由该主体拥有；雇佣、外包、学校或合作关系不存在权利冲突。
- 图标、名称、界面插画、截图、字体与营销素材均为原创或有可再分发授权。
- 任何 AI 生成或辅助生成的代码/美术已进行来源和相似性复核。
- 新仓库接收外部贡献前已有 CLA 或明确的 inbound=outbound 贡献规则。
- 法律顾问已书面确认历史 GPL 发行的处置方案和新版本可发布结论。

## 新仓库创建方式

1. 对整改后的受控文件制作一份无 `.git`、无 `target/`、无本机数据的归档并保存 SHA-256。
2. 在空目录解包，运行 `scripts/check-ip-clean-snapshot.mjs`、完整项目检查和三平台打包验证。
3. 用 `git init` 创建首个提交；不要保留旧 commit、tag、Release、fork 关系或旧版本号。
4. 先建私有仓库，由权利人和法律顾问验收；通过后再公开并发布全新版本。
5. 为 `main` 启用分支保护，把 CI、许可扫描和产权快照检查设为必需检查。

## 证据保全

旧仓库若最终删除，删除前至少在仓库外保存：完整 bare mirror、所有 Release 元数据与
资产、SHA-256、各 tag 源码、工作流日志、下载统计、许可证演变记录、第三方授权往来
以及整改后的法律意见。该档案不得随新公开仓库分发。

# 历史版本许可证审计

## 结论

- `v1.0.0` 至 `v1.8.1`：根目录没有许可证文件，第一方代码默认保留全部权利；同时应用依赖 GPL-3.0 `epub` crate。
- `v1.8.2` 至 `v1.8.9`：根目录使用 Kunpeng Reader Source-Available License，但仍直接依赖 GPL-3.0 `epub` crate。
- `v1.9.0` 至 `v1.16.0`：根目录继续使用 source-available 条款，并把 GPL-3.0 `epub` 2.1.5 源码 vendored 后链接到桌面应用。
- 上述 tag 均曾在 GitHub Releases 提供公开二进制资产。更换当前版本许可证或删除当前 GPL 代码不会追溯修复已经完成的历史分发。

## 2026-08-27：新项目 Beta 1.1 发行决定

项目负责人已明确确认：此前各版本已撤下、没有需要承接的存量用户，当前仓库
作为重新开发的新项目发行。基于该产品决定，`v1.1.0-beta.1` 获准作为新的
GitHub 预发布版本，`scripts/license-policy.json` 的公开资产门禁已开启。

本次决定的技术依据和边界如下：

1. 当前开发版使用 Apache-2.0 `rbook`，并通过 `crates/epub-parser/` 适配现有
   业务接口；仓库不再链接或保留 `epub-rs` 的 vendored 源码。
2. 发行前已运行仓库的依赖许可证检查、知识产权干净快照检查和包内第三方声明
   检查；这些是工程检查结果，不替代任何外部法律意见。
3. Windows、Linux 和 macOS 资产只能由相应三平台 GitHub Actions 产出并附带
   SHA-256 清单。项目负责人另行授权 `v1.1.0-beta.1` 作为早期开发预发布采用
   临时签名的 macOS 资产；工作流会拒绝把这一路径用于非 prerelease。稳定版仍必须
   完成 Developer ID 签名和 Apple 公证。
4. 该决定只授权当前新项目的 Beta 1.1 预发布；历史版本的许可证事实与本节
   "版本授权边界" 的说明保持不变。

## 版本授权边界

每个版本按接收者取得该版本时有效的许可证判断。后续许可证不能自动收回已经授出的权利，也不能把新权利追溯赋予旧版本。若某个目录或版本曾明确采用 MIT 等不可撤销许可，已取得副本者可能继续依赖该许可；组合二进制是否满足 GPL 则仍需单独判断。

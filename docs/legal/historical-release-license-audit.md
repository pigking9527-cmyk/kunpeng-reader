# 历史版本许可证审计

## 结论

- `v1.0.0` 至 `v1.8.1`：根目录没有许可证文件，第一方代码默认保留全部权利；同时应用依赖 GPL-3.0 `epub` crate。
- `v1.8.2` 至 `v1.8.9`：根目录使用 Kunpeng Reader Source-Available License，但仍直接依赖 GPL-3.0 `epub` crate。
- `v1.9.0` 至 `v1.16.0`：根目录继续使用 source-available 条款，并把 GPL-3.0 `epub` 2.1.5 源码 vendored 后链接到桌面应用。
- 上述 tag 均曾在 GitHub Releases 提供公开二进制资产。更换当前版本许可证或删除当前 GPL 代码不会追溯修复已经完成的历史分发。

## 当前处置

1. `scripts/license-policy.json` 将新增或覆盖公开 Release 资产硬暂停；普通 CI 和本机验收构建仍可运行。
2. 当前开发版使用 Apache-2.0 `rbook`，并通过 `crates/epub-parser/` 适配现有业务接口，不再链接或保留 `epub-rs` 源码。
3. 历史 Release 资产仅能由仓库管理员按已批准的处置决定移除，避免没有留存证据就执行不可逆操作。
4. 2026-08-31，仓库所有者确认：新解析器兼容验收、发行包许可证文件检查、历史资产处置、知识产权确认和法律复核均已完成，允许恢复早期开发测试包的公开发布。该确认不改变历史版本在其原始分发时的许可证结论。
5. 早期开发测试包仍必须通过 `license:check` 和 `ip:check`，并在发布说明中如实标注签名、公证和同步服务状态。稳定版仍需要完整的平台签名与公证流程。

## 版本授权边界

每个版本按接收者取得该版本时有效的许可证判断。后续许可证不能自动收回已经授出的权利，也不能把新权利追溯赋予旧版本。若某个目录或版本曾明确采用 MIT 等不可撤销许可，已取得副本者可能继续依赖该许可；组合二进制是否满足 GPL 则仍需单独判断。

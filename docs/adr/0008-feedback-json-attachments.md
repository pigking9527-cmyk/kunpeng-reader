# ADR-0008：Bug 反馈支持受限 JSON 附件

## 状态

已接受，2026-08-07。

## 背景

“关于 → 提交 Bug”原先只能提交文字和图片。用户导出的“问题记录”以及其他诊断 JSON 无法随反馈一起发送，开发者难以把描述与当时状态可靠对应。JSON 可能包含阅读器状态或用户输入，因此不能自动采集、无限制上传或在旧服务静默忽略时显示提交成功。

## 决定

- 只有 Bug 反馈显示 JSON 附件入口；功能建议不显示该入口。
- 每次最多由用户主动选择 1 个 `.json` 文件，MIME 固定为 `application/json`。
- Base64 解码后的原始文件大小必须为 1–262144 字节，内容必须是 UTF-8 且能解析为 JSON。
- 客户端、桌面命令层和服务端分别执行同一组校验；服务端只保存通过校验的规范化附件，并可将其作为邮件附件发送。
- 成功响应返回 `acceptedAttachments`。提交含附件时，客户端只有在该值不少于请求附件数时才报告成功；没有该字段的旧服务按 0 处理并提示升级服务。
- 附件必须由用户明确选择；应用不得自动附加图书正文、原书文件、API Key、Token、本机路径或私密阅读内容。

## 兼容性

该字段是反馈请求的可选扩展，不属于同步实体，不升级 `syncProtocolVersion`。不含附件的旧客户端请求继续有效；新版客户端向旧服务提交附件时会得到“服务尚未支持”的明确错误，不会误报成功。

## 迁移与回滚

服务端数据库迁移新增非空 `attachments_json` 列，默认值为 `[]`，历史记录无需转换。回滚服务端会失去附件能力，因此在回滚期间应保留客户端的确认检查；文字和图片反馈仍可继续提交。

## 验证

1. 有效的小型 UTF-8 JSON 可以随 Bug 反馈提交并被服务端确认；
2. 超过 256 KB、非 UTF-8、无效 JSON、错误扩展名或第二个附件均被拒绝；
3. 功能建议窗口不显示 JSON 入口；
4. 旧服务未返回 `acceptedAttachments` 时，客户端不显示附件已提交成功；
5. 历史反馈迁移后 `attachments_json` 为 `[]`。

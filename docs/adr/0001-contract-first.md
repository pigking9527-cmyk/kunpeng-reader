# ADR-0001：跨端先统一契约，再分别实现界面

- 状态：已接受
- 日期：2026-07-27

## 背景

桌面端已经是成熟的 Rust/Tauri 应用；Android 与 iOS/iPadOS 需要原生体验。若直接复制桌面数据库或强行把全部 UI 改成同一框架，会带来高迁移风险，并使阅读排版、高亮定位和平台交互倒退。

## 决定

以 `contracts/` 中的同步实体、API 说明和 fixtures 作为跨端唯一事实来源。桌面、Android、Apple 各自实现 UI 与本地存储；服务端对协议版本保持兼容。纯粹的 EPUB 解析、文本定位等逻辑只在稳定后逐步抽取为可复用核心。

## 后果

- 优点：避免平台界面相互拖累，便于采用 SwiftUI、Compose 和 Tauri 的原生优势。
- 成本：同一界面会有多份实现，需要共享验收场景和设计文档。
- 禁止：任何端直接以另一端 SQLite 表结构或未记录的字段推断同步行为。

## 验证

每次共享语义变更都必须更新 schema、fixture 和兼容测试；所有端需能读取上一协议版本的样本。

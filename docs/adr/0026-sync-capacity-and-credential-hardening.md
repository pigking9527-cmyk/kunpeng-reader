# ADR-0026：同步容量准备与凭据加固

- 状态：已接受
- 日期：2026-08-12

## 背景

生产同步服务仍处在 SQLite 单机阶段，但客户端增长可能形成同时启动、集中重试和多账号并发写入。此前 macOS/Linux 的登录 Token 只经过可逆包装，服务端数据库也直接保存 bearer token；每个数据库连接重复运行迁移检查，每次 push 扫描账号存储用量并清理历史，都会扩大 SQLite 写锁的临界区。

## 决定

1. Windows 使用 DPAPI、macOS 通过 Security.framework 原生 API 使用 Keychain、Linux 使用 Secret Service 保存登录 Token；本机 SQLite 只保存平台凭据引用。旧值首次成功同步时迁移。
2. 服务端只保存 bearer token 与短验证码的服务端密钥 HMAC；兼容读取迁移前且尚未过期的数据。
3. 客户端使用指数退避和随机抖动，启动自动同步额外错峰；本机待同步实体在任何失败后继续保留。
4. 库存摘要和 reconcile 可以按当前设备启用的实体种类过滤，使按类暂停同步时仍能完成账号重置后的自愈校验。
5. pull 同时受实体数量和响应字节预算约束；push 继续按实体数与字节数分批。
6. SQLite 阶段将迁移检查限制为每个进程/数据库一次，账号存储量由同一事务中的触发器维护，Token 活跃时间节流写入，历史按账号每天最多清理一次，批量 push 一次预留服务端 revision。
7. 密码 scrypt 使用独立并发槽，避免认证洪峰占满全部同步请求；过载明确返回 429/503。单进程阶段只有无账号状态的通用请求、健康检查和更新查询使用内存令牌桶，认证、同步、反馈及账号限流仍持久化到数据库；扩为多进程前必须改用共享限流存储。
8. 只在本机暴露 Prometheus 文本指标，并提供默认拒绝远端目标的有界压测脚本。

同步实体、LWW、墓碑、`data_generation` 和协议版本 v3 均不改变。

## PostgreSQL 生产切换

2026-08-12 已在停写窗口将生产后端从 SQLite 切换为 PostgreSQL 18.4。数据库仅监听回环地址，API 通过有界连接池使用无 DDL 权限的运行账号；按用户的 push 和持久化限流使用 PostgreSQL 事务咨询锁保持多进程语义。

切换前已生成 SQLite 快照，核对 18 张表、11,665 行、4,664 个实体及内容无关摘要。切换后已验证真实客户端同步、公网健康接口、数据页校验和物理/逻辑备份。不使用 SQLite/PostgreSQL 长期双写；SQLite 及旧版集群只作为短期可回滚点。

## 安全与兼容

- HMAC 密钥必须来自服务器私密环境，不得进入仓库或日志。
- Linux 没有 Secret Service 时拒绝保存新 Token，不回退明文。
- 现有 Token 在服务端迁移后仍保持有效，数据库只留下摘要。
- `/internal/metrics` 仅允许回环来源；不输出账号、Token、邮箱、实体内容或真实 IP。

## 验证

- 服务端 HTTP 兼容测试覆盖 Token/验证码摘要、O(1) 用量账本、filtered inventory/reconcile、配额、恢复和并发冲突；
- Rust 测试覆盖凭据旧值迁移、批次、cursor、重试和库存摘要；
- 本机压测记录吞吐、P50/P95/P99 和 429/503；
- 生产部署前创建并校验快照，部署后验证健康、指标、同步和备份定时器。

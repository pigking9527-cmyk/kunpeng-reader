# ADR-0031：同步协议 v5 与跳转回退设置断代

- 状态：已接受
- 日期：2026-08-13

## 背景

项目仍处于破坏性开发阶段。用户已明确删除阅读器的旧 1–10 级跳转回退大小设置，
不保留读取、换算、镜像写回或服务端兼容层。继续将旧级别保留在 `app_settings_v1`
会让客户端、契约和服务端对同一设置有两种事实来源。

此前 ADR-0021 与协议 v4 的相关说明属于历史兼容设计；它们不能再约束新基线。

## 决定

1. `syncProtocolVersion` 升级为 **5**。所有 `/v1/sync/*` 请求必须显式声明
   `X-Sync-Protocol-Version: 5`；缺失、v4 或其他值一律在读取实体或写入数据库前拒绝。
2. `app_settings_v1/default` 的跳转回退大小只使用必填的整数
   `readerJumpBackIconSizePx`，闭区间为 30–160。`readerJumpBackSizeLevel` 永久退役：
   payload 中出现它、或缺少像素字段，均为无效 v5 payload。
3. 客户端本地设置和本地 SQLite 中残留的旧字段必须在 v5 写入/同步前删除；不得把
   旧级别转换为像素值，也不得重新写出兼容镜像。没有像素值的旧本机设置采用当前 v5
   默认像素大小，而不是推断旧级别。
4. 其余未知字段仍按 `app_settings_v1` 的字段补丁规则保留；此保证明确不包括已退役的
   `readerJumpBackSizeLevel`。实体名和 payload `version: 1` 保持不变，因为它们不是
   该字段的语义版本号。
5. 旧 Python 服务已从仓库移除；历史运行记录仅保留为证据材料，不构成可运行的回滚
   路径。不得双写、协议翻译或混用 v4/v5 会话。

## 切换、验证与回滚

协议 v5 尚未宣布可部署。切换前必须同时满足：

1. Axum 服务对认证、push、pull、inventory、reconcile、密钥状态/重置、数据重置、
   资产和账户概览等桌面实际调用的 wire 语义完整对齐；仅提升协议请求头不构成对齐。
2. 桌面客户端不再发送 v4 请求体/响应模型，且 v5 服务端对 app-settings 的运行时校验
   与 JSON Schema 一致。
3. 在受保护、空的 PostgreSQL v5 测试库完成桌面到 Axum 的端到端、migration、幂等、
   恢复/数据清除、资产、备份和反向代理演练。
4. 切换前取得可恢复的完整 v4 数据库快照，并将所有参与设备升级到 v5；不支持混合
   版本继续写入。

若任一验收失败，停止切流并恢复切换前的完整 v4 数据库快照和 v4 二进制。该回滚只在
v5 正式写入前或以完整环境恢复的方式进行；不得从已写入 v5 的实体反向构造旧级别，
也不得从 v5 写入构造或恢复已移除的旧 Python 服务状态。

## 后果

- 设置模型只有一个可验证、可测试的像素大小来源。
- v5 是新的开发数据基线，旧开发数据和旧客户端不获得兼容承诺。
- ADR-0021、ADR-0029 与 `api-v4.md` 保留为历史材料；当前实现以本 ADR、
  `api-v5.md`、schema 与 fixture 为准。

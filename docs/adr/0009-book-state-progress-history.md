# ADR-0009：`book_state_v2` 的每日阅读位置历史

## 状态

已接受，2026-08-07。

## 背景

桌面端的既有 `BookSyncStateV2` 已把 `progress_history` 作为可选字段同步。每个 `ProgressTimelineEntry` 记录一次阅读位置摘要，但此前契约未正式描述该字段，Android 也没有持久化它，导致 Android 在写回完整 `book_state_v2` 时会发送空数组，可能覆盖从桌面端拉取的历史。

## 决定

`book_state_v2.payload.progress_history` 是单本书的每日最后阅读位置摘要，而不是阅读统计，也不含书籍正文或本机路径。条目字段为：

- `at`：Unix 秒；
- `progress`：0–100 的全书进度百分比；
- `chapter`：章节索引；
- `frac`：0–1 的章节内比例；
- `position`：可选的续读位置与锚点。

合并目标和输入条目时，客户端以**本机当地日历日**分组；同一天只保留 `at` 最大的条目。结果按日期升序，最多保存最近 3650 个日摘要。`at` 相同的条目按后合并的输入替换先前条目，从而让当前保存的位置成为该秒内的最后值。

该字段缺失时等同空数组。客户端读取未知或暂不使用的 `book_state_v2` payload 字段后，必须持久化并在后续完整状态写回时原样保留；不得用本机的默认空 `progress_history` 覆盖已拉取数据。服务端继续按实体保存不透明 JSON，不解释或重写该字段。

## 兼容性

- `syncProtocolVersion` 维持 1：这是已存在字段的正式契约化和 Android 对齐，不改变实体信封、冲突字段或字段含义。
- 旧客户端没有该字段时，较新客户端以空历史处理；旧客户端若会重写整个 payload，仍须遵循未知字段保留约定，否则无法保证该客户端不会丢失扩展字段。
- 服务端已经对 `book_state_v2` 保存并返回不透明 JSON，无需新增服务端字段白名单或迁移。

## 替代方案

- 将历史转为独立实体：会改变已有桌面字段与同步粒度，拒绝。
- 在 Android 仅显示而不持久化历史：下一次本地写入仍会覆盖远端历史，拒绝。
- 以 UTC 日分组：与既有桌面端按本地阅读日统计的行为不一致，拒绝。

## 迁移与回滚

Android 本地数据库增加 JSON 持久化列；升级时空数组和空未知字段对象为默认值。回滚到不认识该列的 Android 版本不会改变服务端数据；重新升级后仍从同步实体拉取并合并。无需迁移服务端。

## 验证

1. 旧 payload 缺失 `progress_history` 可以读取；
2. 同一日的多条输入只保留 `at` 最大者，跨日保持升序并限制至 3650 日；
3. Android 拉取桌面历史后，本地保存位置会合并并上传非空历史；
4. Android 写回后保留桌面 payload 的未知字段；
5. 服务端 push/pull 仍按不透明 JSON 往返该字段。

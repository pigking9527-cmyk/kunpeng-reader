# ADR-0016：用户标签与收藏夹使用独立同步实体

## 状态

已接受。

## 背景

`book_state_v2` 曾同时保存阅读位置、书签、高亮、评分、用户标签和收藏夹。旧版或字段不完整的客户端读取整本状态后再写回时，会把自己不认识的 `tags`、`collections` 默认成空数组，并以更新的实体时钟覆盖云端。实体级 LWW 无法区分“旧客户端不知道该字段”和“用户明确清空”，因此一次旧版写回可能批量清除分类关系。

## 决定

新增两个协议 v1 可选实体，实体 ID 都是图书内容 SHA-256：

- `user_book_tags_v1/<content_id>`：payload 为 `schema_version: 1`、`content_id` 和规范化 `tags` 数组；
- `book_collections_v1/<content_id>`：payload 为 `schema_version: 1`、`content_id` 和规范化 `collections` 数组。

独立实体存在时始终权威，包括数组为空的情况；活跃空数组表示用户明确清空。`book_state_v2.tags` 与 `book_state_v2.collections` 暂时保留为旧客户端兼容镜像，但新版客户端不得用它们覆盖已存在的独立实体。只有对应独立实体完全不存在时，新版客户端才可从非空旧字段一次性播种；启动投影不得把本机默认空值解释为删除。

用户明确新增、删除、重命名或批量整理后，客户端必须立即写入相应独立实体。标签编辑只写 `user_book_tags_v1`，收藏夹编辑只写 `book_collections_v1`；另一个实体不会因本次操作被创建或清空。冲突继续使用实体级 LWW。

## 兼容性影响

这是协议 v1 的加法扩展，`syncProtocolVersion` 保持 1。旧客户端继续使用和同步 `book_state_v2` 的阅读进度、书签、高亮等字段；它不认识新 kind 时必须忽略，服务端也不会因旧客户端库存缺少这些 kind 而删除它们。旧客户端对旧镜像的标签/收藏夹编辑不再具有跨端权威性，升级后以独立实体为准。

离线核心迁移包 v1 继续只允许原有四类实体，并通过 `book_state_v2` 的兼容镜像携带分类，避免让旧迁移包解析器因新 kind 拒绝整个包。新客户端导入后会从非空兼容镜像播种独立实体。

## 替代方案

继续要求所有客户端完整保留未知 payload 字段不能保护已经发布或来自旧分支的客户端；服务器按客户端版本维护 `book_state_v2` 字段白名单仍无法可靠识别错误声明版本的开发构建。把标签和收藏夹拆出后，旧客户端根本无法写到新实体，故选择独立实体。

## 迁移与回滚

桌面端首次升级先创建恢复点，再仅从本机或已拉取的非空旧字段为缺失的新实体播种；已存在的新实体永不被启动投影覆盖。服务端增加两个 kind 的保存、拉取、盘点和配额支持，不物理改写既有 `book_state_v2`。Android、iOS 后续按相同规则迁移。

回滚到旧客户端时，新实体留在服务端，旧客户端仍能同步旧字段；重新升级后再次拉取权威独立实体。删除新实体 kind 或把独立空数组回填成“缺失”都属于破坏性回滚，不允许静默执行。

## 验证

- 独立非空或空实体均覆盖 `book_state_v2` 的兼容镜像；
- 仅当独立实体缺失时，非空旧字段才播种一次；
- 旧客户端随后上传空 `book_state_v2.tags/collections` 不改变独立实体；
- 标签和收藏夹的显式新增、清空、批量修改与重命名只更新对应 kind；
- 服务端 push/pull/inventory/reconcile 接受并保留两个新 kind；
- 核心迁移包 v1 的允许名单保持不变。

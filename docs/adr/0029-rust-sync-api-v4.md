# ADR-0029：Rust 同步服务与协议 v4（历史，部分被 ADR-0031 取代）

- 状态：部分被 ADR-0031 取代（历史记录）
- 日期：2026-08-12

## 背景

> 本 ADR 保留 v4 的服务迁移依据。协议 v5 的破坏性设置断代、切换前置条件和回滚
> 规则以 ADR-0031 为准；不得把下文的 v4 基线当作 v5 兼容承诺。文中 Python 服务的
> 叙述均为当时背景；其源码现已移除，不能作为当前可运行回滚方案。

作出本决定时，同步 API 是 Python `ThreadingHTTPServer` 应用，已承担认证、限流、同步、
恢复、资产和邮件等职责。项目仍处于开发期且尚无用户，允许清空开发数据并让所有客户端
接受不兼容 API；不为尚未投入使用的旧实现永久背负迁移和双栈成本。

## 决定

1. 新建独立 Rust HTTP 服务，采用 Axum + Tokio + Tower + SQLx + PostgreSQL。
2. 同步数据语义升级为 `syncProtocolVersion: 4`；公开 URL 继续使用 `/v1`。
   URL 版本是 HTTP 表面版本，同步协议版本是数据语义，不把两者强行绑定。
3. 协议 v4 不接受秒级实体时钟、`ai_reader_history_v1` 数组实体或无协议声明的同步请求。
4. 账户密码只接受 Argon2id PHC 字符串，不兼容旧 scrypt 摘要。服务端仅存储会话
   令牌的带域分离 HMAC 摘要。
5. SQLx migration 是 Rust 服务的 schema 唯一入口；不由应用在请求期即席建表。
6. 每个请求具有不含用户数据的请求 ID，统一 JSON 错误与 `Retry-After`；日志、指标和
   OpenAPI 不包含令牌、邮箱、IP、阅读内容或实体 JSON。
7. Python 服务在 Rust 实现通过契约、空库部署和回滚验证前继续作为临时生产基线；
   不导入旧开发数据，不双写，不长期维护两套业务实现。
8. 注册使用仓库 `registration-v2` 契约；验证码 HMAC 摘要与账户创建状态存 PostgreSQL，
   邮件先原子写入 outbox，SMTP 投递由独立 worker 重试，不阻塞 HTTP 请求。
9. 注册限流主体先以域分离 HMAC 摘要化再持久计数；同步在写事务内执行 25 MiB 账户
   总量和每日 25 MiB/10,000 接受实体上传配额，超限整批回滚；下载恢复不消耗上传额度。
10. 默认只监听回环且不信任转发 IP 头；只有同机反向代理覆盖写入 `X-Real-IP` 并显式
    开启配置时，注册限流才使用该地址。

## 迁移和回滚

- 在隔离的全新 PostgreSQL 数据库执行 migration，不在旧 schema 上原地升级。
- 切换时停止旧服务并将入口指向空的 v4 数据库；开发人员和测试设备重新注册、登录和同步。
- 若健康或恢复验证失败，停止 Rust 服务并将入口切回 Python 服务；旧开发数据库只作为
  短期回滚快照，不导入 Rust 服务。

## 后果

- 后端获得可组合中间件、异步 PostgreSQL 连接池、结构化错误和编译期类型边界。
- 开发期的客户端需要一次性升级到协议 v4。
- 没有历史数据转换代码，正式出现用户后必须重新评估任何下一次破坏性升级。

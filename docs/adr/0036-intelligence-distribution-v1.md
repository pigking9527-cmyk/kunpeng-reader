# ADR-0036：情报分发 V1 的永久档案、30 日热数据与历史中转

- 状态：已接受
- 日期：2026-08-23

## 背景

现有情报中心具备本机采集、模型初筛、关系判断和审计原型，但其数据位于可清理
缓存，处理由页面生命周期驱动，且没有独立的服务端内容面。把新闻正文加入现有
`/v1/sync/*` 实体会把“公共内容一份”和“按账号同步私有数据”混为一谈，也会把
本机永久档案错误复制到服务器。

## 决定

1. 本机发布主机是公开资讯的唯一永久档案。档案位于
   `app_data_dir/intelligence-hub/`，至少包含 catalog、正文/HTML/图片 SHA-256
   存储、索引、按月归档、发布 outbox 与审计；它必须提供第二磁盘或 NAS 备份。
2. 情报处理由独立后台工作节点执行。打开情报中心只能查询快照和审计，不能触发
   重新采集、重新调用模型或清空队列。
3. 资讯使用独立的 `/v1/intelligence/*` API，不复用 `sync_entities_v4`、
   `news_subscriptions_v1` 或账号私有的同步资产表。正文和图片在服务器全局只存
   一份；账号仅保存能力、偏好、投递、已读/收藏/隐藏及历史请求。
4. 服务器只提供最近 30 日已发布内容。所有读取 SQL 都必须验证
   `expires_at > now()`；到期清理按 `PURGING → 删除投递 → 正文/引用 → 无引用媒体`
   执行。30 日外不能保留标题、正文、URL 或图片。
5. 发布主机以可撤销、安装绑定的 capability credential 工作，权限至少分为
   `intelligence:publish` 和 `intelligence:relay`；普通用户 Bearer token 不能上传
   公共内容。用户资讯能力 `intelligence_feed_enabled` 独立于同步邮箱验证。
6. 每日与事件发布都使用不可变 `PublicationBundleV1`。上传完成前不可见；服务端
   校验 schema 与 SHA-256 后在一个事务中发布。修正必须生成新 revision，不得静默
   改写旧正文。
7. 模型只能产生 `sourceId`、`noteId` 和结构化文本块，不能产生 URL。服务端从已
   验证的来源记录投影 HTTPS `originalUrl`，再构造供客户端显示的引用。
8. 30 日外访问使用 `ArchiveRequestV1` 状态机。发布主机出站长轮询领取任务，上传
   最小临时包；客户端校验哈希并 ACK 后立即逻辑删除，五分钟内物理删除；未 ACK
   的包最多保存 24 小时。长轮询必须使用独立并发槽和超时，不占普通读取配额。
9. 内容偏好属于账号；投递确认和 SSE 恢复游标可附带已注册的 `deviceId`，并按
   `(account_id, device_id)` 持久化。未携带设备标识的旧客户端保持原有账号级确认
   与显式 cursor 语义，不能借此读取或推进其他设备的状态。

## 后果

- 本机必须从 app cache 迁出，并保存抓取版本、段落证据、图片 CAS、模型缓存键和
  发布审计；正文/媒体不能再仅用有界资讯缓存保存。
- 服务端需要独立迁移、权限、发布、投递、媒体、过期清理和历史任务模块。
- 客户端可离线缓存已下载的正式包，但不能重新生成公共事实或绕过服务端权限。
- 设备恢复必须先完成账号内设备注册；设备撤销后，其确认与游标随外键删除，旧
  连接无法继续更新该设备状态。
- `contracts/intelligence/` 是上述 API、包格式和状态机的唯一跨端事实来源；新增端
  点必须先更新此目录和兼容性 fixture。

# ADR-0030：桌面端只保留一套 UI 实现

- 状态：已接受
- 日期：2026-08-13
- 取代：ADR-0025 中“渐进双轨页面”的部分

## 背景

桌面端曾同时保留 `ui/` 完整页面和若干 React iframe/独立页候选实现，并通过 loader、超时回退和“打开旧版完整页面”切换。这会让同一业务出现两套 DOM、样式、生命周期和测试，并已导致层级、行为不一致与维护成本上升。

## 决定

1. 当前桌面产品的唯一 UI 实现是 `ui/` 下的命令式 HTML/CSS/JavaScript 界面。
2. 同一业务只能有一个可达页面、一个可视组件树和一套样式。禁止备用 iframe、候选页、隐藏挂载、双轨 loader 和“新版/旧版”回退按钮。
3. `apps/desktop-ui/` 可保留无视图的 TypeScript 状态机、业务规则、controller 和 port，但不得存放与现行页面重复的 JSX/TSX/可视组件。
4. 未来更换 UI 技术时，以一个完整业务页为最小切换单元；同一变更必须同时删除被替代页面的入口、DOM、样式和测试。不允许将两套 UI 一起交付到主工作树。
5. 故障处理回到同一页面的空态、错误态或安全的 Git 回滚，不依赖另一套产品 UI。
6. EPUB/PDF、分页、选区、手势与高频渲染仍是同一用户界面内的独立引擎边界，不视为第二套产品 UI。

## 自动门禁

- 产品 HTML 不得加载 React 业务入口、候选 iframe 或双轨 loader。
- 源码不得出现“打开旧版完整…”类切换文案。
- 顶层 Node 依赖不再保留 React 运行时或 React Vite 插件，除非新 ADR 已批准一次性全页切换。
- `ui/tests/governance.test.cjs` 检查上述约束。

## 后果

产品页面的行为、叠层、键盘操作和测试只需维护一份。技术栈整体迁移的单次切换要求会更高，因此必须先在无视图边界和测试中完成准备，再做可视层替换。

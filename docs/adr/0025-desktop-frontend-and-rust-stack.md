# ADR-0025：桌面前端与 Rust 技术栈

- 状态：部分被 ADR-0030 取代
- 日期：2026-08-10

## 背景

桌面端已有较大规模的 HTML、CSS 与 JavaScript，并同时承担阅读渲染、书架、设置、同步和系统集成。长期维护目标要求模块可独立演进、多人并行修改、类型检查和稳定的测试边界；但一次性重写会中断现有功能并造成高风险合并。

## 决定

1. TypeScript 仍用于业务状态、规则和 Tauri 边界；可视层的唯一实现与切换规则改由 ADR-0030 定义。
2. 既有 JavaScript 与 TypeScript 渐进共存；只在新增或修改相邻模块时迁移，禁止全量改后缀式重写。
3. EPUB/PDF、分页、选区、手势和高频渲染属于独立阅读引擎，继续使用命令式 TypeScript/DOM/Canvas，不由 React 管理其渲染循环。
4. Rust 桌面框架固定为 Tauri 2。窗口、菜单、文件、数据库、同步、系统集成和高耗时任务继续在 Rust；桌面端不再引入 Leptos、Yew 或 Dioxus 等第二 UI 框架。
5. 只有在新建独立 Rust HTTP 服务且需求确实出现时，默认采用 Axum + Tokio；现有服务不得为了语言统一而重写。
6. 前端对 Tauri 的调用集中在类型化适配层；跨端实体与 API 含义继续以 `contracts/` 为准。

## 后果

- 新业务边界获得严格类型、标准测试工具和可扩展的团队协作方式。
- 阅读性能敏感部分不承担虚拟 DOM 和大规模迁移风险。
- TypeScript 无视图模块可与现行 UI 并存，但不得再形成另一套页面。
- 构建链会增加 Node/Vite 依赖；桌面发布仍由 Tauri 打包静态产物。

## 替代方案

- **保持全部原生 JS**：短期依赖少，但大规模状态、DOM 生命周期和多人协作成本持续上升。
- **Vue + TypeScript**：可行且迁移更温和，但本决定优先面向大规模团队生态、组件库与长期招聘，选择 React。
- **Svelte + TypeScript**：轻量且性能好，但不作为本项目长期主 UI 栈。
- **全量重写**：拒绝。它会阻断日常开发、造成无法审查的大变更，并难以回滚。
- **Rust UI 框架替代 Web UI**：拒绝。会新增第二套 UI 渲染和组件体系，不能降低现有桌面端维护成本。

## 落地状态与后续演进

当前只保留 `ui/` 命令式产品页面。已抽取的 TypeScript state/port/controller 作为无视图业务边界保留；重复的 React 页面、挂载宿主、loader 和回退链已由 ADR-0030 禁止。阅读页的 EPUB/PDF、分页、选区、手势与高频渲染继续作为同一 UI 内的独立命令式引擎。

后续改动以行为回归、严格类型检查和跨平台构建为门禁；发生回归时通过修复或回滚提交处理，不在产品内维持两套业务界面。

## 验证

- 前端严格类型检查必须覆盖实际 TypeScript 源码；
- 新模块必须有单元测试，Tauri 交互增加集成或端到端验收；
- 桌面端改动仍按现有规则构建完整应用；
- 同步实体或 API 改动继续先更新 contracts 和兼容性 fixture。

# ADR-0024：可同步书单元数据与本地检索优先的大模型推荐

状态：已接受。

## 背景

`book_collections_v1/<content_id>` 已经负责收藏夹/书单成员关系，但书单的简介、封面、人工排序一直只保存在本机 `library.json`。这使得跨设备时成员能回来，书单本身的呈现和编辑内容却无法回来。新增的“书库问答 → 大模型推荐书单”还需要为每一本入选图书保存一段与提问相关的评语。

## 决定

新增可选同步实体 `booklist_v1/<list_id>`，payload 为 `version: 1`、稳定 `id`、`name`、`description`、可选 `coverContentId` 和有序 `items`。每个 item 只包含 `contentId` 与可选 `review`。`contentId` 是图书完整内容 SHA-256；本机书籍 ID、路径、封面缓存路径、原书文件、正文、向量与索引不得进入 payload。

- 书单成员关系仍由 `book_collections_v1` 权威保存。`booklist_v1` 只补充书单元数据、顺序和逐书评语；接收端只把它投影到已经存在的本地图书，不因远端元数据创建无路径的书架条目。
- 手工新建的空书单可以存在，并同步为空 `items`。删除书单必须同时写入成员关系的显式清空和 `booklist_v1` 墓碑。
- 书库推荐必须先在本地语义索引中粗选候选书；只有候选书的标题、稳定本机 ID、少量命中片段和已有本地标签可发送给用户已配置的大模型。模型只可从候选 ID 中精选，并为每本书生成与用户问题有关的短评；解析或校验失败时不得保存书单。
- 推荐结果先在书库问答页面展示，用户明确命名并保存后才写入书单。保存后的逐书评语仍可在书单中手工编辑。

## 兼容性与同步范围

这是协议 v3 的加法扩展，`syncProtocolVersion` 保持 3。旧客户端忽略未知 kind；服务端保留实体及墓碑。`booklist_v1` 归入现有“书签、高亮、批注、评分、标签、收藏夹与书单”同步开关。关闭该开关时不上传、不下载，不删除任何本机或云端书单副本；重新开启后从头拉取这一分类。

## 验证

- schema 与 fixture 可校验包含评语的 `booklist_v1`；
- 本地推荐只向模型发送本地检索候选，且模型返回的每个 ID 都属于候选集合；
- 保存、重排、手改评语和删除正确写入 `booklist_v1` 与必要的 `book_collections_v1`；
- 同步投影不携带路径、正文或本机 ID，并保留未知 payload 字段。

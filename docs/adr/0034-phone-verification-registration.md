# ADR-0034：手机验证码注册与短信滥用边界

- 状态：接受
- 日期：2026-08-13

## 背景

现有 v5 服务通过邮箱验证码完成两阶段注册。国内用户可选择手机验证码降低注册门槛，但短信
按条计费，号码也是个人信息；客户端还无法保守可信地保护任何短信密钥。因此手机注册不能
复用客户端直调云短信、明文长期保存号码或“发送后立即创建账号”的实现。

## 决定

保留现有邮箱注册，新增可选的手机两阶段注册：

1. `POST /v1/auth/register/phone/start` 只接收账号、E.164 手机号与安装 ID。服务端完成手机号、
   IP、网段、安装 ID 和全局持久化限流，受每日短信安全额度约束后创建 5 分钟挑战和 outbox。
2. 短信供应商只在服务端配置。首个适配器使用腾讯云 SMS API 3.0 的 TC3-HMAC-SHA256；
   未完整配置时手机号入口明确返回不可用，不降级为日志、固定验证码或客户端密钥。
3. 服务端只有在供应商明确接受投递后才允许 `POST /v1/auth/register/phone/confirm` 消费验证码。
   验证码最多尝试 5 次；成功后一次性消费并创建账号和首个设备会话。
4. 账号表仅保存带域分离的 keyed HMAC 手机摘要、末四位和验证时间。完整号码与验证码只在
   短期挑战/outbox 中存在；投递成功、最终失败或注册成功后清空 outbox 敏感字段，过期记录
   最晚 24 小时清理。应用日志不得记录完整号码、验证码、供应商请求或密钥。
5. 每日额度以事务内 reservation 计数，失败投递也不返还，以避免故障/攻击期间无限重试消耗。
6. 手机验证表示当时控制该号码，不表示真实身份；账号仍使用密码、设备会话与既有同步世代。

## 边缘与源站

API 域名无法对客户端隐藏。正式部署应把稳定 HTTPS 域名置于边缘代理/WAF 后，源站只监听
回环或只允许边缘回源，并由同机受信代理覆盖 `X-Real-IP`。若源站 IP 曾公开，切换边缘后应
更换源 IP。应用层限流不能被边缘策略替代。

## 兼容性

该变更新增 `/v1/auth/*` 路由和认证数据，不改变 `syncProtocolVersion` 或同步实体。旧客户端
继续使用邮箱注册；新客户端可在服务能力允许时选择手机注册。密码找回仍依赖已验证邮箱，
手机号注册账号应在客户端提示后续绑定邮箱，直至单独定义手机找回契约。

## 部署与回滚

部署前须先迁移 PostgreSQL，再配置已审核的短信应用、签名和模板；模板变量顺序固定为
“验证码、有效分钟数”。先以测试号码验收投递和确认，再开放入口。回滚时可移除短信配置使
手机入口 fail closed；已通过手机注册的账号及摘要不能删除，邮箱注册不受影响。

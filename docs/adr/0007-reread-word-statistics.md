# ADR-0007：重读内容计入阅读字数

## 状态

已接受，2026-08-06。

## 背景

`reading_bucket_v2` 的 `words` 用于记录用户实际阅读获得的字数信用。此前桌面端把已计入页码持久化，并使同一页在任何后续阅读中都不能再次贡献字数。这把“阅读量”错误收窄为“唯一页覆盖量”，无法反映用户为理解内容进行的重读。

## 决定

`reading_bucket_v2.payload.words` 表示该时间桶内的**有效阅读字数**，不是图书内去重后的唯一字数。因此，用户重新进入一页并满足当前平台的有效阅读门槛后，重读应再次累加字数；累计字数可以大于图书的总字数。

同一次页面停留的周期结算必须只补充本次停留尚未获得的部分，不能因定时器重复累加。客户端仍应保留可见文本计数、停留时间、失焦/遮罩暂停和快速来回翻页抑制等反刷量措施；各平台可采用不同的原生实现，但不得因“此前已经读过该页”拒绝一次新的有效重读。

## 兼容性

- `syncProtocolVersion` 维持 1：实体结构和冲突字段不变，只明确既有 `words` 的累计语义。
- 历史桶继续有效；新版本只会在以后产生的有效重读中增加新的 `words` 增量。
- 旧客户端不会丢失该字段，但可能低估重读量；Android 与 Apple 客户端应在各自阅读统计实现中对齐本决定。

## 替代方案

- 将字数永久限制为每本书唯一字符数：不能表达复习、精读和重新阅读，拒绝。
- 每次翻页无条件累加：易被快速来回翻页放大，拒绝。

## 迁移与回滚

无需迁移数据库或服务端。回滚桌面实现只会停止未来的重读增量，不修改已经同步的历史桶。

## 验证

1. 同一页在一次停留中多次周期结算，只累计到该次停留应得的额度；
2. 离开后重读同一页并满足停留门槛，会产生新的额度；
3. 快速连续翻页和失焦状态仍不应获得完整额度；
4. 新增的 `reading_bucket_v2` 仍可被旧客户端和服务端读取。

# 从 v1.16 到测试版 1.0：开发沿革

> 本文把旧版 `v1.16.0` 与当前“测试版 1.0”（技术版本
> `1.0.0-beta.1`）之间的产品、工程和发布边界连成一条可追溯的记录，
> 并在末尾补充测试版 1.1 的增量事实。
> 它只归纳仓库现有的 Git、更新日志、ADR 和协作文档；不是对未完成
> 部署、真实跨平台验收或公开发行作出的承诺。

## 1. v1.16：旧版集中重构与功能积累

`v1.16.0` 的更新记录保存了当时的产品快照：阅读器继续覆盖 EPUB/PDF、单页/双页与滚动阅读、脚注与书内跳转、批注/高亮、章节进度和跨章定位；设置集中管理外观、分页、工具栏与高级选项；书架、统计、账户、同步、资讯和 AI 入口也进行了集中调整。

这一阶段的典型用户体验改进包括：

- 双页中缝可调、拖动时以实际阅读页预览，松手后再应用；图片跨页策略、章节尾页和恢复定位分别加固。
- 阅读配色、主题、字号和排版在设置中即时预览；PDF 桥接、长章节与跨章阅读路径补充回归覆盖。
- 书单、标签、书库问答和 AI 历史围绕细粒度同步实体演进；正文、原书文件、原始封面、本机路径、模型和索引始终不进入同步实体。
- 账户、同步、统计和问题记录获得更明确的状态与诊断边界。

当时的记录还写明桌面业务页完成了 React + TypeScript + Vite 的一轮实现。这个事实属于旧版快照；它不能覆盖当前的单 UI 架构决定。

## 2. 许可证整改与产品版本重置

历史许可证审计确认：`v1.0.0` 到 `v1.16.0` 的发行链包含 GPL-3.0 `epub` 依赖，其中 `v1.9.0` 到 `v1.16.0` 还 vendored 了 `epub` 2.1.5 源码。后续替换当前代码或许可证，不能追溯解决已完成的历史发行。

因此项目建立了新的产权基线：当前开发版使用 Apache-2.0 `rbook`，并由 `crates/epub-parser/` 维持业务接口兼容；旧 GPL 源码不再保留或链接。产品版本重置为 `1.0.0`，而不是把旧版 `v1.16.0` 当作可直接升级的前序版本。

同步入口也随之断代：新客户端只使用 `/v1/auth/*` 和 `/v1/sync/*`；旧的无前缀认证/同步路径必须在读取认证、数据库或请求体之前返回 `426 CLIENT_UPGRADE_REQUIRED`。任何破坏性服务数据清空都仍要求受保护备份和明确批准，不能由客户端或文档自动触发。

## 3. 后端：从旧 Python 服务到 Rust / Axum / PostgreSQL

旧同步服务的迁移依据在 ADR-0029 中保留：原实现是 Python `ThreadingHTTPServer`；新服务在独立目录 `server/reader-sync-api-rs/` 中使用 Rust、Axum、Tokio、Tower、SQLx 和 PostgreSQL。服务侧引入迁移文件、结构化错误、速率限制、认证/令牌摘要、同步额度与请求观测边界，并把 schema 迁移交给 SQLx，而非请求期间临时建表。

随后协议继续演进到同步协议 v5。当前事实必须与“代码完成”分开表述：桌面 wire、Axum DTO 与契约测试已对齐，但 v5 尚未完成受保护 PostgreSQL 空库迁移、桌面到服务端的真实端到端、备份恢复、反代切换和受控部署验收；因此尚未切入生产流量。

## 4. 前端：从 JavaScript 页面走向严格 TypeScript 边界

当前不是把可视页面再复制一份再换技术栈。ADR-0030 规定：`ui/` 下的 HTML/CSS/命令式页面是唯一用户可达的实现；不允许候选 iframe、隐藏备用 DOM、双轨 loader 或“新版/旧版”切换。

在这条规则下，JavaScript 到 TypeScript 的工作采用渐进方式：

1. 新增或修改相邻功能时，先抽取纯 rules、状态机、controller、port 和 Tauri 调用边界；这些模块使用严格 TypeScript 且可独立测试。
2. EPUB/PDF 分页、选区、手势和 Canvas/DOM 高频渲染继续保留在命令式阅读引擎，不把渲染循环强行交给第二套 UI 框架。
3. 生成的 classic IIFE 由原有页面加载，页面外观和交互仍只有一份；类型检查、测试和构建门禁覆盖实际 TypeScript 源码。

这解释了“前端 JS 替换成 TS”的准确含义：业务边界正在被 TypeScript 收敛，而不是在产品中保留第二套 TSX/React 页面，也不是已经完成了零 JavaScript 的全量替换。

## 5. AI/Codex 辅助的协作方式（Vibe 开发）

本轮开发使用了 AI/Codex 辅助的多会话协作方式：每个会话先登记 `ACTIVE_WORK.md` 的文件占用，依照 ADR、contracts 和现有测试拆分子任务，完成后留下验证结果或未验证边界。它帮助加快 UI 调整、规则提取、测试补充、诊断和文档整理，但不是运行时功能，也不能替代人工体验验收、签名/公证、PostgreSQL 演练或正式发布批准。

协作流程的硬约束是：跨端语义先更新 ADR 与 contracts；纯 UI 不得借重构建立第二套页面；任何会话都不能把真实正文、账户、令牌、密钥或服务器资料写入 fixture、日志或公开记录。

## 6. 测试版 1.0：当前产品方向

测试版 1.0 建立在上述新基线之上，当前工作围绕以下方向继续推进：

- 阅读器：继续处理阅读页启动、连续打开、页码/章节进度、双页中缝预览、主题与排版的稳定性和可诊断性。
- 智能管理：从分散的模型/索引入口收敛为语义模型、Agent 模型、生图/视频模型三类能力；硬件检测决定哪些大型模型可见、可安装或必须跳过，避免未满足条件时下载 27B 或 H3。
- 情报中心：本机生产链、服务端正式发布包、账号隔离缓存与客户端阅读展示按契约分层；未登录用户不展示受保护资讯服务，模型推理与原始正文不进入同步实体。
- 更新体验：独立更新页与“关于”页分别呈现自动发现与人工检查结果；测试版本和缓存必须可撤销，不能把撤销的更新记录错误恢复为新版本。

测试版 1.0 的三平台持续构建可生成 Windows x64、macOS Apple Silicon 和 Linux x86_64 的测试产物及哈希清单；这只说明构建链在相应 CI 环境可运行。Windows 运行库、macOS Developer ID 签名/公证、许可证审查，以及 v5 同步服务的受控部署仍是公开发行前必须单独完成的门禁。

## 8. 测试版 1.1：从重构基线到可验证的日常迭代

测试版 1.1（技术版本 `1.1.0-beta.1`）不是“v1.16 的直接续版”，而是
在 1.0 新产权与架构基线上的第二个测试版本。它把近期多个会话已完成或已
通过定向验证的工作，以同一条产品线继续记录：

- 智能管理收敛成语义模型、Agent 模型、生图/视频模型三张主卡。普通用户
  只处理准备、暂停、继续与状态；重排、BGE-M3、索引维护和 ComfyUI 等细节
  收进所属能力的设置与维护，不再横跨多页重复配置。
- 27B 与 H3 不以“看得到但不能用”的按钮出现。系统先检查 GPU 显存、内存、
  磁盘空间、可用显存和既有运行时；条件不足就跳过本地安装，原生层仍保留
  第二道拒绝，避免旧页面或脚本绕过判断。
- 资讯消费端按最终 publication bundle 工作：账号和设备各自隔离缓存，SSE
  使用游标续接，图片和正文在完整保存并验证摘要后才确认接收。超过保留期
  的内容走可重试的历史回源状态；客户端不上传原始正文、模型提示或推理。
- 阅读器继续处理连续开书、预加载、页码与章节状态、双页中缝预览和磁盘缓存
  等稳定性问题；这些工作有相应的代码/定向测试证据，但 EPUB/PDF 真实样本、
  性能和视觉验收仍须在隔离 profile 人工完成。
- 更新页与“关于”页改为围绕当前版本和本次发现的新版本呈现。撤销的虚拟版本
  不会靠本地旧缓存重新弹出；测试版 1.1 的完整说明以本文件和更新日志为准。

项目负责人于 2026-08-27 确认历史版本已撤下、没有需要承接的存量用户，并把
当前仓库作为重新开发的新项目授权 Beta 1.1 公开预发布。因此三平台工作流会将
Windows x64、macOS Apple Silicon 和 Linux x86_64 的真实安装包及 SHA-256 清单
上传到同一 GitHub Release。该授权不降低平台验证要求：macOS 必须保持 Developer
ID 签名与 Apple 公证；Windows 运行库、v5 同步服务部署和真实 PostgreSQL 演练的
未完成项仍不能由源码提交、CI 成功或临时安装包替代。

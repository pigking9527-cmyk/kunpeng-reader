# 历史 Python 同步 API 本地端到端验收（pre-v5）

> 本文只保留旧 Python 服务的历史/回滚测试说明。它不适用于当前 Axum v5 基线，
> 不能作为 v5 的 PostgreSQL、协议兼容或部署验收证据。当前 v5 演练见
> [`sync-api-v5-postgres-rehearsal.md`](sync-api-v5-postgres-rehearsal.md)。

本文件定义历史 `reader-sync-api` 的可重复、本地 HTTP 级验收。它不需要真实账号、邮件服务、服务器地址、书库或任何用户阅读数据。

## 运行

在服务端目录运行：

```bash
python3 -m unittest -v test_app test_backup_recovery
```

测试只使用 Python 标准库，并在每次运行时创建临时 SQLite 数据库、临时资产目录和一个 `127.0.0.1` 的随机端口 HTTP 服务；结束后自动删除。若受限沙箱禁止监听回环端口，应在常规开发机或 CI 中执行，而不是改为访问共享/生产 API。

仓库发布检查也会调用同一命令：`scripts/check.ps1` 的“sync server tests”步骤。

## 自动化覆盖的证据

`server/reader-sync-api/test_app.py` 的 `ReaderSyncHttpIntegrationTests` 通过真实 HTTP 请求覆盖：

- 增量 push/pull、实体数与响应字节双重分页、幂等重复投递、LWW 冲突和并发同时间戳收敛；
- 按启用 kind 过滤的盘点/对账、协议 v2/v3 兼容、秒级旧时间戳归一化、无效实体不被错误确认；
- 未验证邮箱拒绝同步；本地邮件发送桩驱动的首次邮箱验证后解锁同步、邮箱换绑、改密撤销其他设备令牌、密码重置撤销旧令牌；
- 数据清除与恢复时间点操作递增 `data_generation`、撤销令牌，并拒绝旧世代写入；
- Token/短验证码 HMAC、O(1) 存储账本、实体恢复历史、账号删除、配额与限流、密钥包世代、资产分块续传/哈希/Range 下载；
- 智读历史内容限制（包括拒绝正文摘录）和更新清单的公开端点。

`test_backup_recovery.py` 额外验证 SQLite 在线快照、压缩、校验和恢复点轮换。测试中的账户、令牌、邮箱和内容均为临时 fixture，不能替换为真实值。

## 两设备与重装的分层验证

服务端测试用同一临时账户的两份独立令牌和不同设备 ID 覆盖首次拉取、增量更新、删除墓碑、冲突、令牌撤销和世代拒绝。它证明 API 的多设备语义，但不证明桌面应用自身把本机数据库正确投影为同步实体。

在最终产品验收中，根会话或验收人员仍须使用两个独立安装实例和专用测试账号完成：

1. 设备 A 首次同步，设备 B 全量拉取后检查进度、书签/高亮/批注、标签、书单、设置与智读历史；
2. 双端离线修改同一实体后恢复网络，检查 LWW 决议、墓碑不会复活；
3. 设备 B 清除本机数据或重装、重新登录并全量恢复；
4. 断网、超时与取消后重试，确认 UI 不泄漏令牌、密码、文件路径或正文；
5. 若启用密码/邮箱功能，向实际可接收的测试邮箱发送并确认邮件；本地邮件桩不验证 SMTP/DKIM/垃圾邮件投递；
6. 在已批准的运维窗口按发布恢复流程，从独立快照抽样恢复并检查校验和、数据库完整性与脱敏账号计数。

不要把真实账号、令牌、邮箱、服务器参数、书籍正文、本机路径、模型或密钥写入测试、文档、控制台输出或 Git。

## 非目标

此套件不访问生产服务，不检查真实证书、DNS、反向代理、邮件投递或对象存储异地副本；这些属于发布/运维验收。它也不替代桌面端 UI 的登录、断网提示、重启恢复和隐私投影验证。

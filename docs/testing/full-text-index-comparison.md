# 全文索引与 SQLite FTS5 对比验收

当前桌面端关键词搜索使用已发布的本地章节索引、Bloom 预筛和内存匹配；它不会在
交互查询中读取原书或建立索引。SQLite FTS5 只是待比较候选，不能因为标准库支持
FTS5 就替换当前实现。

## 前提

1. 使用仓库外、已获准的中文 EPUB/TXT 样本及已安装的桌面应用。不得把书籍、
   解出的章节、文件路径、标题、查询原文或 SQLite 副本提交到仓库。
2. 两种实现必须共享相同的章节提取、Unicode 规范化、停用规则、范围过滤和结果
   上限；FTS5 不得自行改变“命中”的产品语义。
3. FTS5 候选库必须是临时、仓库外文件。演练结束后按样本保管规则清除；报告只保留
   匿名样本 ID、SHA-256、章节/字数级别、计数、耗时和内存，不保留正文。

## 同一批次的测量

针对至少三个中文查询类别（精确短词、四字短语、罕见词）以及有/无书架范围过滤：

1. 冷态各执行 3 次预热，再记录 5 次端到端查询；分别记录 P50/P95、返回书数、
   命中总数、首批预览数、待建索引书数和峰值/稳定工作集。
2. 对每个查询比较按书命中数、章节号与前 8 个片段位置；差异逐项分类为抽取、
   分词、排序、截断或真实 bug。不能只比较“有结果”。
3. 分别记录完整建立时间、增量重建时间、磁盘占用、关闭再开后的首次查询，以及
   10 次连续查询后的工作集。构建期间必须保持阅读窗口优先策略。
4. 使用 `EXPLAIN QUERY PLAN` 记录 FTS5 查询计划（只保留计划文本）；若计划出现
   意外全表扫描、临时排序或无界片段读取，先修复候选实现再比较结果。

## 私有聚合记录工具

`scripts/record-search-index-benchmark.mjs` 只把受控演练环境**已经得出的聚合数值**
写入仓库外 JSON 记录。它不接受任何书籍、SQLite、索引、模型、查询文件或向量文件
路径；不连接数据库，不执行查询，不读取语料，也不复制数据。

传给工具的语料、查询集、每个查询与范围标识均为 64 位小写 SHA-256。查询原文、书名、
本机路径、正文、SQL、`EXPLAIN QUERY PLAN` 原文和向量均不得作为参数。`EXPLAIN` 仅在
受控环境中人工按私有检查表归类为 pass/fail，再将该检查项的哈希标签传入工具。这样
报告仍能验证是否发现全表扫描、临时排序或无界内容读取，而不会泄漏计划文本或查询。

每个查询先在相同条件下预热 3 次，再记录 5 次。工具强制至少记录三个不同的查询标签，
以对应精确短词、四字短语和罕见词；受控私有工作表必须记录每个哈希对应哪个类别。
`candidateRows` 是该阶段候选行数，
`returnedRows` 是最终返回的命中行数；两者均为汇总数，不能替换为片段或书籍标识。
以下占位符必须在受控环境中替换，且只包含哈希或数字：

```sh
node scripts/record-search-index-benchmark.mjs \
  --implementation current-chapter-index \
  --corpus-sha256 <CORPUS_SHA256> --corpus-books <BOOK_COUNT> --corpus-chapters <CHAPTER_COUNT> \
  --query-set-sha256 <QUERY_SET_SHA256> \
  --warmup <QUERY_SHA256>:<SCOPE_SHA256>:<CANDIDATE_ROWS>:<RETURNED_ROWS>:12,11,13 \
  --measurement <QUERY_SHA256>:<SCOPE_SHA256>:<CANDIDATE_ROWS>:<RETURNED_ROWS>:10,11,9,12,10 \
  --plan-check <PLAN_CHECK_SHA256>:pass \
  --output /controlled-records/search-current-index.json
```

对 FTS5 候选执行同一批语料、查询集、哈希标签与测量条件，仅把
`--implementation` 改为 `sqlite-fts5`。生成文件只含实现名称、匿名语料/查询集/指标
标签、聚合书籍/章节/候选/返回行数、P50/P95、检查哈希的 pass/fail，以及明确的隐私
声明；工具拒绝向仓库写入记录。它不是结果生成器：真实基准、命中逐项比对和私有
`EXPLAIN` 审核仍需由受控演练环境完成。

## 决策门槛

仅当 FTS5 在相同语义下不丢失/误报可解释以外的命中、增量与首次查询没有明显退化，
且磁盘/内存/关闭清理满足当前索引的预算，才可提出 ADR 和独立迁移方案。迁移方案还
必须保留旧索引的读取兼容、失败回退和可删除旧索引前的 macOS 人工记录。

在没有上述真实样本记录前，保持现有自研索引，不创建第二个生产索引也不改变默认
查询路径。

# 书架大书库性能基线

`apps/desktop-ui/src/features/shelf/shelf-performance-baseline.test.mts` 使用固定的 **10,000 条合成元数据**检查书架的无视图前端规则：

- 标签/收藏书单的 `all` 组织筛选；
- 全量书名排序；
- 封面 URL 白名单校验。

合成条目只包含稳定 ID、占位标题/作者/摘要标签、数值状态和允许/拒绝的伪 URL。它没有用户书名、正文、本机路径、真实封面或同步内容。运行方式：

```sh
npm run test:typed
```

测试先预热，再取五次运行的中位数。它以每项 **8 秒**为“灾难性回归”门槛：这个刻意宽松的门槛用于捕获意外的二次复杂度、无限重试或未受控 URL 处理，不把开发机、CI CPU、Node/V8 版本差异误判为功能失败。

因此，测试通过不等于已经证明真实 WebView 的首次渲染、滚动、封面网络加载或内存占用。发布验收仍须在目标平台用真实但不提交的书库测量这些指标，并记录设备、应用版本、书库数量、预热状态以及 P50/P95；若某次交互超过 2 秒、滚动持续掉帧或预热后内存随滚动线性增长，应先回滚引入回归的变更，不在产品内另留一套 UI。
